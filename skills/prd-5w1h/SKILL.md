# prd-5w1h — 5W1H로 PRD 초안 만들기

서비스 기획의 뼈대(5W1H)만 받아 **단일 진실 공급원(Single Source of Truth) PRD.md** 초안을 뽑는다.
창작이 아니라 구조화다 — 입력을 PRD 포맷으로 옮기고, 비어 있는 필수 항목만 최소 질문으로 채운다.

## 입력 계약

**필수(없으면 묻는다 — 한 번에 모아서):**
- 서비스명, 한 줄 정의
- 5W1H 6개 전부:
  - **Why** — 왜 만드는가 (해결할 불편·문제)
  - **Who** — 누구를 위한 것인가 (타겟 사용자)
  - **What** — 무엇을 만드는가 (핵심 기능·제공물)
  - **When** — 언제 사용되는가 (사용 맥락·타이밍)
  - **Where** — 어디서 사용되는가 (플랫폼·환경)
  - **How** — 어떻게 만들 것인가 (수익 모델·기술 접근)

**선택(없으면 추론하고 초안에 "(초안)" 표기):**
- 환경 (기본값: 데스크톱 웹 우선)
- 페이지 구성(라우트) — What에서 도출. 없으면 최소 구성(랜딩·핵심 기능·인증)으로 제안
- 기술 스택 — How에서 도출. 없으면 프로젝트 관용 스택 추천안으로 제시
- 페이지 수·라우트 목록을 사용자가 명시했으면 그대로 유지한다

정보 없이 호출되면 아래 양식을 그대로 보여주고 채워 달라고 한다:

```
## 프로젝트 정보
- 서비스명:
- 한 줄 정의:
- 환경: (예: 데스크톱 웹 우선)
## 5W1H
- Why:
- Who:
- What:
- When:
- Where:
- How:
## 페이지 구성 (라우트) — 선택
## 기술 스택 — 선택
```

## 절차 (순서 고정)

1. **입력 파싱** — 사용자가 준 블록에서 필수 항목을 읽는다. 빠진 필수 항목이 있으면 **한 번에** 묻는다(질문을 여러 번 나누지 않는다).
2. **추론** — 라우트·기술 스택 미제공 시 What/How에서 도출한다. 추론한 값은 PRD에 "(초안)"으로 표기한다. 구조가 갈리는 모호점(예: B2B인지 B2C인지 불명)만 질문하고 나머지는 진행한다.
3. **생성** — 아래 출력 포맷 그대로 `PRD.md`를 쓴다.
4. **저장·중단** — 저장 위치는 프로젝트 루트(git 리포면 git root, 아니면 cwd)의 `PRD.md`. 쓰고 나면 후속 수정·구현 제안 없이 멈춘다.

## 출력 포맷 (고정 — 순서·구조 바꾸지 않는다)

### 문서 최상단 두 블록

**A. 「이 문서에 대하여」**
- 이 PRD가 앱 전체 기획서이자 단일 진실 공급원임을 명시
- 참조 방법: 섹션 번호 지정(예: "§3.2")·앵커 링크
- 변경 원칙: 코드가 PRD와 어긋나면 **PRD를 먼저 업데이트**한다
- 관련 문서: 디자인 시스템은 `DESIGN.md`를 참조한다는 안내
- 섹션 용도 표: 각 섹션을 언제 참조하는지 한눈에 보이는 표

**B. 「목차」**
- 본문 모든 섹션의 앵커 링크. 주요 기능·페이지 구조는 하위 항목까지 전부 링크

### 본문 5개 섹션 (번호 매김 + 앵커 필수)

**1. 프로젝트 개요** — 정확히 3줄. 서비스명·한 줄 정의·핵심 가치를 압축.

**2. 타겟 페르소나** — 1~2명. Who에서 도출하되 각 페르소나에 페인 포인트(Why와 연결)를 붙인다.

**3. 주요 기능 5가지** — What을 기능 단위로 나눈다. 각 기능에 사용자 흐름(입력→처리→결과)을 붙인다. 하위 번호 3.1~3.5.

**4. 페이지 구조**
- 사용자가 명시한 라우트는 그대로 유지
- 전역 레이아웃(글로벌 헤더·푸터 등 공통 요소)을 먼저 서술
- 각 페이지마다 들어가는 섹션·컴포넌트·상태를 상세히 풀어쓴다 (예: 랜딩이면 히어로/기능 소개/사용 사례/요금제 미리보기/CTA, 검색 결과면 검색 바/필터 정렬 바/카드 그리드/빈 상태/페이지네이션)
- 빈 상태·로딩·에러 상태도 각 페이지에 명시
- **시각적 스타일(컬러·타이포·레이아웃 무드)은 적지 않는다** — `DESIGN.md` 영역

**5. 성공 지표** — 세 카테고리 각각 정량 목표:
- 가입 전환 (예: 랜딩→회원가입 전환율)
- 결제 전환 (예: 무료→유료 전환율)
- 재방문/리텐션 (예: 주간 재방문율, 월간 이탈률)
입력에 없는 수치는 합리적 초안값을 두고 "(초안)" 표기한다.

## 규칙 (레드 플래그)

- **디자인 방향 금지** — 컬러·폰트·무드·구체 레이아웃 수치를 PRD에 넣지 않는다. 필요하면 "디자인 시스템은 `DESIGN.md` 참조" 한 줄만.
- **지어내기 금지** — 입력에 없는 사실(매출 목표·출시일·경쟁사 수치)을 단정하지 않는다. 추론값은 반드시 "(초안)" 표기.
- `PRD.md`가 이미 있으면 덮어쓰기 전에 확인한다 — 기존 내용과 다른 방향이면 사용자에게 묻는다.
- 작성 후 다른 작업 없이 멈춘다. "이어서 구현할까요?"도 하지 않는다.
